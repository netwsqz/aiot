这些是**已经决定不做**的，别再翻出来：

### 1.1 的五个场景

来自 `NEXT-STEPS-2026-07.md` P0。背景：`docs/BUGFIX-REPORT-2026-07.md` 修了 5 个 CRITICAL + 13 个 HIGH，**全是静态修复，一条没在真机上跑过**，之后的日志全是修复前的。2026-09-19 的烧录验证了固件能启动，但这五个没测。

1. **深睡眠循环** —— 双击 PWR 睡 → 唤醒 → 再睡，重复 10 次以上。看：不 panic、唤醒后触摸仍工作、PSRAM 不随循环增长
2. **WiFi 自愈** —— 拔路由器电源 30s 再插上，看设备是否 ~60s 内自动重连
3. **计时器并发到点** —— 3 个 1 分钟提醒同时到点，看满屏闹钟是否逐个弹出
4. **Web 配置热加载** —— 连 AP 改天气城市 → 立即刷新，看是否免重启生效
5. **TODO API 边界** —— curl 发超长 name/text，看返回 400 而不是截断存储

**硬边界**：只测这 5 个 + 断电恢复（拔电再上电，检查 NVS 数据完好）。**测完就停**，不许扩成「稳定性马拉松」——「稳」没有终点，会吃掉全部预算。

## Phase 2 — 宠物的记忆（~24h）

背景：`pet_ui.c` 里**零处 NVS 引用**。宠物每次深睡眠唤醒都像第一次见你——「刚清空待办 → 庆祝」靠的是上一轮状态差，一断电就没了。

这一段的定位：**记忆不是 AI 的替代品，是 AI 的前置条件。** 没有记忆，接上 LLM 也只能说空话（「今天也要加油哦」）；有了记忆才说得出来只有这台设备说得出的东西。

### 2.1 记忆层（~10h）

一个 NVS namespace + 单 blob，遵循 `TodoMgr_*` / `TimerEngine_Persist/Restore` 既有模式。

| 字段 | 用途 |
|---|---|
| `first_seen` | 相处天数 |
| `last_seen` | 「好久不见」判定 |
| `todo_done_total` | 里程碑 |
| `pomodoro_total` | 里程碑 |
| `streak_days` | 连续使用天数 |
| `poke_count` | 被撸次数 |
| `last_greeting_day` | 同一天不重复打招呼 |

**必须注意**：冷启动和深睡眠唤醒是**两套初始化路径**（见 `CLAUDE.md`），两边都要读。

### 2.2 表达层（~14h）

用记忆驱动新状态和对白。这一块开放，第一刀先切四件事：

1. **久别重逢** —— >3 天没见
2. **里程碑** —— 第 N 个番茄钟 / 第 N 个待办完成
3. **连续天数** —— 连续使用 N 天的状态
4. **不重复打招呼** —— 同一天只打一次
