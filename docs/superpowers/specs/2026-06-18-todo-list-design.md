# TODO 清单功能设计文档

**日期**: 2026-06-18
**状态**: 设计完成，待实现

---

## 1. 概述

为 AIoT 墨水屏设备增加 TODO 清单功能，支持手机通过 WiFi AP 直连上传任务清单，墨水屏多页面显示，触摸操作。

### 核心需求

- 手机通过 WiFi AP 热点连接设备，浏览器打开 Web UI 管理任务
- 墨水屏独立显示页面（仪表盘 + TODO 清单），触摸左右滑动切换
- 支持多清单、任务优先级、截止日期、完成状态
- 任务数据持久化到 NVS，掉电不丢失
- 截止日期到期的任务在屏幕上高亮显示

### 非目标

- 不做语音提醒/蜂鸣器
- 不做云端同步
- 不做 OTA 网页单独更新
- 不做用户认证（AP 无密码或简单密码）

## 3. 数据模型与 NVS 存储

### NVS namespace: `todo`

**清单元数据** — key: `lists`

```json
[
  { "id": "l_001", "name": "工作", "icon": "💼", "order": 0 },
  { "id": "l_002", "name": "购物", "icon": "🛒", "order": 1 }
]
```

**任务数据** — key: `l_001`（每个清单一个 key）

```json
[
  {
    "id": "t_001",
    "text": "完成报告",
    "done": false,
    "priority": 2,
    "due": "2026-06-20",
    "created": 1750252800
  }
]
```

### 设计要点

- 每个清单一个 NVS key，读写独立
- 任务 ID 用 `t_` + 时间戳生成
- 优先级：0=普通，1=重要，2=紧急
- 截止日期格式：`YYYY-MM-DD`，空串表示无截止日期
- 内存缓存一份副本，读操作不访问 NVS，写操作同步回 NVS
### 分块存储策略

NVS 单个 value 限制约 1900 字节，因此每个清单的任务分块存储：

- `l_001_count` → 任务总数（uint16）
- `l_001_0` → 第 0-11 号任务的 JSON 数组（约 1800 字节）
- `l_001_1` → 第 12-23 号任务的 JSON 数组
- ...以此类推，每块最多 12 条任务

单个清单最多 100 条任务 → 最多 9 个分块 key，NVS 容量完全够用。

读取时按 count 计算需要读哪些块，写入时只更新变更所在的块。

## 4. REST API

基地址：`http://192.168.4.1`（AP 默认网关）

| 方法 | 路径 | 说明 | 请求体 |
|------|------|------|--------|
| GET | `/api/lists` | 获取所有清单 | — |
| POST | `/api/lists` | 新建清单 | `{"name":"工作","icon":"💼"}` |
| PUT | `/api/lists/{id}` | 修改清单（名称/图标/排序） | `{"name":"新名称"}` 或 `{"icon":"📌","order":0}`（字段均可选，按需更新） |
| DELETE | `/api/lists/{id}` | 删除清单（级联删除所有任务） | — |
| GET | `/api/lists/{id}/tasks` | 获取清单下所有任务 | — |
| POST | `/api/lists/{id}/tasks` | 新增任务 | `{"text":"写报告","priority":1,"due":"2026-06-20"}` |
| PUT | `/api/tasks/{id}` | 修改任务 | `{"done":true}` 或 `{"priority":2,"due":"..."}` |
| DELETE | `/api/tasks/{id}` | 删除任务 | — |
| GET | `/` | 返回嵌入式网页 | — |

### 响应格式

成功：`{"ok":true, "data":{...}}`
失败：`{"ok":false, "error":"message"}`

### 级联删除行为

`DELETE /api/lists/{id}` 级联删除该清单下的所有任务。返回值中包含删除的任务数量：

```json
{"ok":true, "data":{"deleted_tasks": 7}}
```

同时清除对应的 NVS key（`l_001_count`、`l_001_0`、`l_001_1` 等）。

### 设计要点

- 网页 HTML 嵌入固件，GET `/` 直接返回
- 任务变更后通过回调通知 LVGL 刷新墨水屏
- AP 热点 SSID: `AIoT-TODO`

## 5. WiFi AP 热点管理

### 触发方式

长按 BOOT 按键（IO0）2 秒开启热点。

### 状态机

```
IDLE ──长按BOOT──► AP_ON ──15分钟无操作──► IDLE
  ▲                   │
  └───再次长按/上传完成──┘
```

### 设计要点

- AP 默认 15 分钟自动关闭，避免忘记关
- 开启时墨水屏状态栏显示 WiFi AP 图标 + IP 地址
- `wifi_ap` 组件提供 `WifiAp_Start()` / `WifiAp_Stop()` / `WifiAp_IsActive()` 接口
- 关闭时自动断开所有客户端，任务数据已持久化到 NVS 不会丢失
- 与现有 `wifi_bsp`（STA 模式）互斥 — AP 开启时暂停 STA，关闭后自动恢复 STA 连接（如已配置 WiFi 凭据）
- AP 启动失败 → 墨水屏显示 "AP 启动失败，请重试"，5 秒后恢复原页面
- 掉电重启 → 默认不自动恢复 AP，需再次长按开启

## 6. 墨水屏 TODO UI 设计

### 页面结构

触摸左右滑动切换：

- **Page 0**: 仪表盘（现有，不动）
- **Page 1**: TODO 清单列表页
- **Page 2+**: 每个清单的任务详情页

### 清单列表页布局

```
┌─────────────────────────┐
│ ◄  18:30   Wed Jun 18   │ ← 状态栏（时间+电池+WiFi+AP）
├─────────────────────────┤
│  我的任务清单           │
│                         │
│  > 工作        3/7 [x] │ ← 点击进入详情页（> 表示选中）
│  > 购物        1/5 [x] │
│  > 学习        0/3 [x] │
│                         │
│  ← 左滑回仪表盘         │
└─────────────────────────┘
```

### 任务详情页布局

```
┌─────────────────────────┐
│ ◄  18:30   Wed Jun 18   │
├─────────────────────────┤
│  > 工作       [!!!]    │ ← 优先级标记
│                         │
│  [x] 完成报告   06/20   │ ← 已完成（灰色删除线）
│  [ ] 写代码 review !今天│ ← 未完成+到期高亮
│  [ ] 开周会      06/22  │
│                         │
│  v 下滑查看更多          │ ← 超出屏幕时显示
│                         │
│  ← 左滑回清单列表        │
└─────────────────────────┘
```

### 触摸操作

- 左右滑动 → 翻页
- 点击任务 → 切换完成/未完成
- 任务区上下滑动 → 滚动列表（任务多时）
- 截止日期到期 → 任务前显示 ⚠ 图标

> **字体说明**：SSD1681 是单色屏，emoji 无法直接渲染。墨水屏使用 LVGL 内置字体，优先级用 `[!]`/`[!!]`/`[!!!]` 文字标记，完成用 `[x]`/`[ ]` 标记。Web UI 手机端不受此限制，正常使用 emoji。

### 墨水屏刷新策略

- 翻页 → 全刷（清晰）
- 勾选任务 → 局部刷新（快速，无闪烁）
- 自动同步 → 每 30 秒检查数据变更，有变化才刷新
- 数据变更频率过高（手机连续操作）→ 合并刷新，最多每 2 秒刷新一次
- 局部刷新失败 → 回退全刷

## 9. 错误处理与边界情况

### AP 热点

- AP 启动失败 → 墨水屏显示 "AP 启动失败，请重试"，5 秒后恢复原页面
- AP 运行中掉电重启 → 默认不自动恢复 AP，需再次长按开启

### Web 请求

- 非法 JSON → 返回 400 + 错误信息，不崩溃
- 清单/任务数量超限 → 单个清单最多 100 条，最多 10 个清单，超限返回 409
- 并发请求 → `todo_manager` 内部用 mutex 保护，Web 和 LVGL 可同时操作

### 墨水屏刷新

- 数据变更频率过高（手机连续操作）→ 合并刷新，最多每 2 秒刷新一次
- 局部刷新失败 → 回退全刷

### NVS

- NVS 写入失败 → 内存缓存仍有效，下次重启前重试
- JSON 解析失败 → 忽略损坏数据，日志告警
