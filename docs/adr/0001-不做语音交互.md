# 不做语音交互

**Status**: accepted

## 背景

项目名是 "aiot"，仓库里躺着一份 1200 行的 `components/ai_engine/ai_engine.c`（有 ASR/LLM 链路的实现），但它是**孤儿**：没有 `CMakeLists.txt`、不在任何 `PRIV_REQUIRES`、没被 `main.cpp` 调用。

`CLAUDE.md` 和 `docs/NEXT-STEPS-2026-07.md` 都写「从 `.worktrees/weather-feature` cherry-pick `ai_ui` + `audio_bsp` 即可接回」——**这个说法是错的**，下次别照着做：

- `components/ai_ui/` **从未进过 git**（`git log --all -- components/ai_ui` 为空），磁盘上也不存在
- `ai_engine.h` 不存在，而 `ai_engine.c:24` 就 `#include "ai_engine.h"` → 这份 .c 现在连编译都过不了
- `audio_bsp` 只有 `V2/08_Audio_Test/components/audio_bsp/` 一份微雪示例，不是可直接引用的顶层组件

所以「接回 AI」的真实成本 = 补一个头文件 + 从零写界面 + 抄一个音频组件 + 调通链路，**20–40 小时**。

## 决定

**不做语音交互。** 设备不接收语音输入、不提供对话。

「智能」改用**无人值守的自动反应**表达：宠物根据设备状态自己变表情，不需要你说任何话。

## 理由

语音是**交互型功能**——必须由人开口操作才有意义，与项目定位（`常显` + `不打扰`，见 `CONTEXT.md`）方向相反。为它花掉预算的一大半，换来的功能跟主张打架。

而「智能感」的现有实现已经够用且有 9 个输入：TODO 数量（HAPPY/BUSY/ANXIOUS）、番茄钟运行（FOCUS）、电量（LOW_BATT）、时段（SLEEP/GREETING）、TODO 清空（CELEBRATE）、久坐（REST）。全部不需要人操作。

## 考虑过的其他选项

- **按原计划做完整语音**（Qwen ASR + DeepSeek LLM）—— 放弃，见上。
- **只做文本 LLM，不做语音** —— 放弃。设备没有键盘输入，没有语音就只剩 Web 配 TODO 那条路，仍然违反「常显不打扰」；且内存风险实打实（DIRAM 已 ~85.7%，ai_engine 需 8KB×2 任务栈 + WS/HTTP）。
- **保留入口但默认关闭** —— 放弃。YAGNI，真要做时这份 ADR 直接被 supersede 即可，不需要预留开关。

## 后果

- `components/ai_engine/ai_engine.c` 留在树里但不编译。**不要删**（修过 5 个静态 bug，是重做时的起点），也**不要按 `CLAUDE.md:138` / `README.md:133` / `NEXT-STEPS` P1 那些步骤去「接回」它们——那些步骤是错的。**
- 文档里「AI 语音是核心卖点」的说法作废。
